# Backend: админ-панель и сообщения

Текущий сайт — статический GitHub Pages. Статические страницы могут отображать данные и отправлять посетителя во внешние каналы связи, но сами по себе не могут безопасно аутентифицировать администратора, хранить сообщения или отправлять их владельцу.

## Что уже подготовлено

- публичные данные вынесены в `data/site-data.json`, `data/changelog.json` и `data/achievements.json`;
- фронтенд загружает эти JSON-файлы без встраивания секретов;
- контакты ведут в существующие GitHub, Telegram и Discord профили;
- контактная форма может подготовить Telegram draft через публичную ссылку с текстом; пользователь сам отправляет сообщение в приложении.
- подробная схема CMS описана в `admin/README.md`.

## Что нельзя включать без backend

- пароль или токен администратора в браузерном JavaScript;
- запись сообщений в локальное хранилище браузера с обещанием, что владелец их получит;
- «авторизацию» на основе скрытого URL или статического пароля;
- публичную форму, которая показывает «успешно отправлено», не имея реального получателя.

## Предлагаемая реализация следующего серверного этапа

Backend на Cloudflare Workers или Node.js:
- GitHub OAuth через GitHub App для единственного администратора;
- обновление JSON через GitHub API с созданием PR;
- endpoint формы обратной связи с серверной валидацией, rate limiting и антиспамом;
- уведомление в выбранный владельцем канал;
- журналирование без сохранения лишних персональных данных.

Перед развёртыванием нужно выбрать хостинг, домен API и способ получения уведомлений. Секреты задаются только в панели хостинга.
