# Управление содержимым портфолио

## Почему здесь пока нет публичной админ-панели

Сайт размещён на GitHub Pages и работает как статический frontend. Он не может безопасно хранить GitHub Personal Access Token, пароль администратора или секретный ключ в JavaScript. Любой посетитель может скачать клиентский код и прочитать такие значения.

Поэтому в этой версии не добавлена фиктивная «защищённая» форма входа. До подключения backend контент управляется через GitHub.

## Где редактировать данные

- `data/site-data.json` — публичный статус и активные направления.
- `data/changelog.json` — история обновлений.
- `data/achievements.json` — подтверждённые этапы.
- `roadmap.html` — план развития.
- Страницы `*-*.html` — подробные кейсы проектов.

Изменения следует вносить в отдельной ветке и отправлять Pull Request. После проверки PR можно объединить с `main`; GitHub Pages опубликует статические изменения.

## План полноценной CMS

Для настоящей панели управления нужен отдельный backend (например, Cloudflare Worker или небольшой Node.js API) и OAuth-авторизация через GitHub App. Токен приложения хранится только в серверных Secrets.

Предлагаемая схема:

1. OAuth login через GitHub App; разрешить доступ только владельцу репозитория.
2. Backend проверяет GitHub identity и роль, не доверяя данным из браузера.
3. API читает и обновляет JSON-файлы через GitHub Contents API.
4. Каждое изменение создаёт ветку/commit или Pull Request, а не меняет опубликованный `main` напрямую.
5. Включить rate limit, CSRF-защиту, проверку схемы JSON и журнал действий.
6. Не принимать и не хранить пароли посетителей в собственной базе без реальной необходимости.

## Планируемые API

- `GET /api/site-data`
- `PUT /api/site-data` — только для авторизованного владельца.
- `GET /api/changelog`
- `POST /api/changelog` — создание записи через PR.
- `GET /api/achievements`
- `POST /api/achievements` — создание записи через PR.

## Что требуется для запуска CMS

- выбранный backend-хостинг;
- GitHub App с минимальными разрешениями Contents: read/write и Pull requests: read/write;
- OAuth callback URL;
- серверные Secrets для App ID, private key и OAuth secret;
- домен/API URL и настройка CORS.

Пока эти параметры не настроены, безопасное управление выполняется через GitHub UI. Не вставляйте токены в HTML, CSS, JavaScript или JSON-файлы репозитория.
